## Exact predictor semantics and risks

`project_points`: points numeric non-null; season mean; L5 only when >=5 valid values otherwise season mean; L10 only when >=10 otherwise season mean. Baseline = .45*season + .35*L5 + .20*L10. Average minutes over non-null MIN, else user minutes; minute factor = projected/average if average>0, else 1. Defense adjustment = .10*(opponent DEF_RATING - unweighted league team mean). Pace = .35*(opponent PACE - league team mean)*projected_minutes/48. Rest >=2 => +.4 else -.4; home +.35 else -.15. Final max(0, baseline*minute_factor + adjustments). It is an uncalibrated heuristic, not betting line advantage or predictive confidence.

`fetch_matchup_context` defaults rest=3 on failure, clips computed rest 0..5 after subtracting one off-day, and defaults home=0 on failure/no scoreboard match. Missing opponent advanced row defaults league averages. These defaults are silently certain in old UI; web port must expose estimates/missing data and not treat failed context as measured. Uses host date and scoreboard V2, needs NBA date/schedule support and bounded calls. Legacy fetches long 60-second endpoints, not suitable as-is in async handler.

## Exact CV semantics and risks

Team roster service requires total returned log rows >= window, takes `head(window)` before dropping null values per stat; pandas sample SD (`ddof=1`) with <=1 valid value assigned 0; mean<=0 OR SD<=0 excludes that player/stat. Thus constant positive scorers and all-zero stocks are excluded from the team ranking, not ranked first. It records games=window even when nulls reduce sample: web must show valid count separately. Ascending CV is **most consistent**, despite user wording “top CV”. UI first 15. Tier thresholds CV*100 <30 Elite, <50 Good, <70 Average, else Variable. Failed individual logs silently skipped previously; web needs partial failure counts. Roster is season-selected but traded-player history isn't filtered to games for that team. Separate player profile convention differs: nonpositive mean -> CV 0; single valid game -> SD 0; per-stat recent windows newest non-null values.

## Exact slate semantics and risks

Season dashboard per-game MIN>=25 and GP>=5, slate team IDs. Per-player returned log len>=5, PTS coerced/dropna; L5 over newest valid values; L10 when >=10 valid values else L5. Projection .60*L5 + .25*L10 + .15*season dashboard PTS. `diff` = projection - season dashboard mean, include abs(diff)>=3; OVER if positive otherwise UNDER; sorted descending abs(diff). No sportsbook line, injury/minute forecast, probability or uncertainty model. Old default season hardcoded 2025-26; failed player fetches skipped. Need partial failures + dynamic selected season/date; don't describe heuristic difference as validated wagering edge.

## Exact defense semantics and risks

Ranking ascending opponent overall FG%, tiers rank 1..5 Elite, 6..15 Good, 16..20 Average, 21..25 Below Avg, rest Poor. Not adjusted for shot quality/volume. Five standard zones: restricted area, non-RA paint, midrange, corner 3, above break 3. Two corners are **unweighted mean of left/right percentages**, not attempts-weighted. Existing service fills missing zones 0 and analytics safe_float fills invalids 0; these must be unavailable in honest web views, never best defense. League averages are unweighted means of team percentages, not league shot-weighted rate. MultiIndex schema extraction assumes `(zone, OPP_FG_PCT)` and first column team ID; schema regression necessary.

## Player/profile formulas and source limitations

[player_data.add_derived_columns](../nba_terminal/services/player_data.py#L134) uses PTS+REB+AST (PRA), PR/PA/RA, STL+BLK (stocks), eFG=(FGM+.5*FG3M)/FGA, TS=PTS/[2*(FGA+.44*FTA)], 3PAr=FG3A/FGA, FTr=FTA/FGA, PTS/FGA. Legacy helper fills missing values with zero; current web analysis deliberately preserves missing inputs and zero-denominator rates as unavailable. Mean of game percentages differs from ratio of season totals: new profile labels both explicitly. Hit rates count >= threshold, not strictly greater; denominators are valid returned game values, not calendar games/DNPs. No predictive interpretation. Opponent filtering based on matchup abbreviation. Current player summary sample SD, mean<=0 CV=0 retained and disclosed.

Legacy profile shooting split data set attribute is `assited_shot_player_dashboard` (provider spelling), plus overall, area, 5ft/8ft, shot type summary. Provider drift should be surfaced. All six measures were separate full league calls for every profile, 60s timeouts and permanent disk cache with no freshness expiry; don't reuse this orchestration in browser. New PLAYER path uses shared in-memory batch Advanced with 12s requests and 15-minute TTL via bounded worker/cache.

Archive docs mention sample percentiles and hit-rate plots, but missing helper modules mean exact percentile interpolation, ddof, tie handling, chart file naming, exports and zero cases cannot be verified. `archive/d.py` has import-time deletion and execution: read only. No other root/archive predictor/ML training model is present at this accepted revision despite heavy dependencies in pyproject. No usable trained artifact or calibrated forecast is established.

## Revision2 implemented parity and remaining concrete source limits

All six retained player profile measure groups and all six shooting breakdowns are implemented in PlayerSeasonMeasures/PlayerShootingBreakdowns. Additional league batches load only when selected; shooting tables load on explicit request. No six-request initial chain. ProfileSampleExplorer independently selects opponent/stat/window/threshold, compares two requested seasons in the same selected phase, and reports mean/sample-SD/CV, interpolated quartiles, max and valid-sample hit rates with per-season game links. Does not assume unavailable helper interpolation/exports. Source tables remain separate from computed game-log ratios.

Live 2024-25 Playoffs requests succeeded for Base, Advanced, Misc, Scoring, Usage, Defense and all six shooting breakdowns; public fixtures retain real headers/rows. Usage MIN=851 is total minutes while Base MIN=37.0 is per game for the same GP=23 despite PerGame requested. Browser labels Usage total minutes; Base/other MPG. Base DD2=5/TD3=0 are counts, not per-game rates. DEF_WS is exposed as NBA provider DEF_WS rather than claiming a locally validated win-share calculation. Raw provider columns absent in a requested season are displayed unavailable (—), never invented. Shooting zero-attempt percentages are unavailable.

Original Player Analytics supported multiple simultaneously entered players and season cards; this browser deliberately focuses one searched player, with two season samples side by side and all stat choices. Multiple-player visual juxtaposition and exact archived PNG export formatting remain explicit presentation gaps, not unsupported data. Archived helper source files are absent, so exact print/chart/export reproduction is not available. Search directory is nba_api's bundled static data and can lag new signings.

Legacy player_data hit-rate implementations fill missing values with 0 before threshold tests; current web uses only valid game values. Legacy rolling_summaries only emits 5/10/15 when enough returned rows exist; profile recent summaries use up to 5/10/20 newest valid values. These are separate original semantics and web shows counts explicitly.
