# Pure waiver optimizer interface v1

`from nba_terminal.services.fantasy_optimizer import plan_waivers`
`plan_waivers(payload: dict) -> dict` has no network, writes, clock, or transactions.

Required payload: `dates` sorted remaining ISO dates (today only if games not started); `current_totals` and `opponent_totals`; `players`; `lineup_slots` (list, e.g. PG, SG, SF, PF, C, UTIL, UTIL); `weekly_add_limit`, `used_adds`, `available_adds`. Optional `max_stream_slots` default 4; `beam_width` default 8; `candidate_limit` default 40; `margin_sd` keyed by nine category names, or `prior_week_margins` >=3 complete weekly margin mappings. Explicit uncertainty is necessary for modeled probability/recommendations. Category names: pts, reb, ast, stl, blk, threes, to, fg_pct, ft_pct. Totals/rates keys: pts, reb, ast, stl, blk, threes, to, fgm, fga, ftm, fta. Player rates also require minutes. No percentages are summed.

Player: `id` unique str; `owner`: user/opponent/other/free; `positions`: eligible lineup slot strings (UTIL accepts anyone); `schedule`: ISO date list, explicit empty allowed; `current_rates` optional full rates; `current_games` sample count; `prior_rates` optional full rates; `eligible` bool default true; `locked` bool default false (cannot drop); `unavailable_dates` optional ISO dates for injuries/locks; `injury_status` optional string (out/inactive excludes all future games). Locked means transaction lock, not forced starter. Adapters must mark uncertain injury/schedule information in `data_gaps` and omit unsupported recommendations by withholding required data. All other-team players remain ineligible even if eligible=true. Daily lineup caps represented by exact slot list; per-date overrides via `lineup_slots_by_date` optional mapping. `data_gaps` optional string list.

Output: status ready/incomplete/unavailable; reasons; baseline and projected forecasts; actions (date, add_id, drop_id, stream_slot, gains, probability_gain); remaining_adds; provenance; assumptions; limitations; data_gaps. Forecasts include raw totals, expected scheduled/started games and minutes, per-category user/opponent values, direction-adjusted margin, winning/tied/losing/unknown state and modeled win probability, plus probability of >=5 category wins. Incomplete data returns explicit status and null probabilities, with no actions. Normal independent category-margin model is a transparent sensitivity estimate, not calibrated betting odds; correlations, injuries and rate shifts remain limitations. Ties do not count toward five wins. Search is bounded, approximate, deterministic, and may return fewer than allowed adds. No re-adds of any acquired player; only initial roster stream slots may rotate, max 4 by default. Prior rates blend with small current samples using 10 prior-equivalent games; full current rates used at >=10 games. Original payload is never mutated.

The production adapter in `nba_terminal/services/fantasy_planner_adapter.py` supplies the authenticated snapshot and confirmed constraints through POST `/api/fantasy/espn/plan`. It uses a smaller 500-evaluation production budget, preserves provenance and returns precise missing inputs. See [the workspace guide](fantasy.md) for confirmations, historical/sensitivity modes and limitations. The pure function itself performs no authentication and invents no live data.

## v1.1 contract alignment (ESPN provisional v1 inspected)
`locked` must now be an explicit boolean for every relevant player; omitted/null is unavailable, never coerced to false. `weekly_add_limit`, `used_adds`, `available_adds` require nonnegative integers; ESPN unknown weekly counters must stay unknown until trusted complete-period accounting or explicit user confirmation. Adapter must carry provenance of such confirmation. API schedule objects must become only unstarted, transaction-effective ISO dates; null schedules cannot become empty. Confirm missing injury/eligibility/lineup rules or pass `data_gaps` to suppress recommendations and probabilities. This pure module does not authenticate or establish those facts. ESPN `current_games` numeric samples must be verified integral before adapter conversion. Slot names must match player eligibility (UTIL wildcard). Backend prior matchup totals can supply prior signed category margins for uncertainty; >=3 nonconstant samples per category required and not calibrated. No fixed uncertainty constants are silently supplied.

Runtime bounds: 1–14 remaining dates, <=1000 normalized players, <=20 lineup slots, candidate_limit <=100, beam_width <=32. Optional `evaluation_limit` default 2000, maximum 5000. `search` exposes evaluation count and limit exhaustion. More candidates than candidate_limit are approximated by single-game marginal value; schedule value is evaluated in full forecasts after shortlisting. Improving-only search can miss combinations requiring an initially harmful move. Each action also exposes `category_probability_gains`, `games_gain`, `minutes_gain`. Negative category gains are explicit tradeoffs. `max_stream_slots` clamps to 4. Only trusted, caller-provided constraint inputs can yield ready recommendations. All data gaps suppress probabilities.
