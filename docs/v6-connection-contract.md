# V6 connection lifecycle contract

`useLeagueFantasy` retains `snapshot` during a same-context refresh/transient failure. Its optional additive `lifecycle` field is `{state: 'connected' | 'refreshing' | 'stale' | 'reconnect-needed', resultIdentity: string | null, action: string, readOnly: boolean}`. Unknown/disconnected or definitive 401/403 invalidates the snapshot. Transient network/429/5xx preserves it read-only. A team/league/season/session identity change invalidates old context immediately. `loading` describes a snapshot request, not disconnection; never use it as a key or conditional mount for strategy.

`snapshotIdentity(snapshot)` excludes observational fetched_at/evaluated_at/as_of metadata, normalizing equivalent fresh/cached provider TTL states while retaining stale/failed/unknown status and all actual facts, source completeness, dates, usage evidence and expiry. Plan effects use this identity plus serialized preferences, never snapshot/status object identity. `useWaiverPlan` returns `{plan,busy,error,lifecycle}`; last good plan remains visible read-only while updating or stale. A new incompatible context must remount the strategy. Changed preferences/data retain the previous result only as a read-only reference until the matching request completes. `resultIdentity` is the identity of the displayed result; consumers may present an Updating/Stale badge using `action`. Do not execute recommendations when `readOnly` is true.

API failures are `FantasyApiError` with sanitized `status`, `code`, `retryable`, `reconnectNeeded`; never infer logout from a generic exception. Polls are single-flight, visibility/focus coalesced and cleaned up. Plan retries are bounded (2 automatic retries per request identity); periodic source polling uses exponential failure backoff capped at 60 seconds.

ENGINE pickup filter contract: API accepts `pickup_filters`; `PlannerPreferences.pickup_filters` now accepts optional numeric min_minutes/min_games/min_participation; ENGINE validates/defaults each. No engine validation is bypassed here. Existing usage declaration leases remain immutable; expired evidence is not renewed by refresh.

Implementation exports: `FantasyLifecycle`, `snapshotIdentity`, `useWaiverPlan` from `web/src/fantasy-lifecycle.ts`; `useLeagueFantasy` from `web/src/use-league-session.ts` (also re-exported at its original LeagueFantasy import path). `onPlan` may accept a second optional AbortSignal; the production API client now honors it. Keep the strategy key limited to league/season/team/matchup identity. Pass `loading` as the hook's refreshing argument and `!!error` as blocked, never conditionally omit the strategy on these flags.

`useLeagueFantasy.lifecycle.resultIdentity` identifies the retained snapshot; plan lifecycle identity identifies the displayed plan plus its preferences. If identities differ or readOnly is true, present the retained plan as reference, with the concise action/badge. Auth 401/403 classification excludes local request/team-selection validation (for example team_not_owned); those do not mean the account logged out. A successful credential renewal does not clear a failed normalized source flag.

The extension's public `pair_id` is non-secret lifecycle identity only; cookies/nonces remain authenticated and never enter page events. Same-context session renewal retains `context_id`; a replacement account/connection gets a new identity. The updated packaged extension zips must ship with the source fix. Existing installed extensions require normal user update/reload; no browser installation or permission change was performed here.

A renewed bridge session expiry is capped by the original pairing consent expiry; normal renewal never extends the 30-day pairing lease. Identity strings are opaque machine values, not user-facing text.
