# ESPN backend contract v1

> Data-source update: [Fantasy data V2](fantasy-data-v2.md) supersedes the original weekly-count, schedule, injury and drop-metadata limitations below. V2 uses verified ESPN matchup counters/droppable fields and bounded NBA enrichment; unknown health follows available-unless-out authorization. Planner/UI behavior is documented separately by its owning workstream.

Base `/api/fantasy/espn`. Read-only unofficial ESPN basketball adapter. All responses use `Cache-Control: no-store`. Errors: HTTP 400/401/403/404/409/413/415/429/502/503/504 with `{detail:{code,message}}`; never echo credentials or upstream bodies.

Local single-process deployment only: routes require loopback client AND loopback Host; same-origin requests, JSON mutations and `X-Fantasy-Request: 1`. Browser uses credentials same-origin. Cookies remain backend-only after initial explicit POST; no OAuth/password handling. Session cookie `nba_espn_session` is opaque HttpOnly SameSite=Strict, Secure on HTTPS, path `/api/fantasy/espn`, expires after 8 hours. In-memory sessions, cap 64. Restart disconnects. Multiuser remote hosting needs a real authenticated secret store before enabling these routes.

- POST `/connect`: JSON `{league_id:positive int,season_id:2019..2100,team_id?:positive int,swid?:string,espn_s2?:string}`. Supply both private cookies or neither. Values only in POST body, never URL/storage/logs. Returns status below; sets cookie after successful fetch. Connect with no team_id to discover teams. Private selection must match returned team owners against SWID; public selection is explicitly unverified (public data cannot prove ownership).
- GET `/status`: `{connected:boolean,league_id?,season_id?,team_id?,auth_mode?:public|private,ownership_verified?:boolean,teams?:[{id,name,selectable,ownership_verified}],expires_at?}`. Disconnected returns only connected=false.
- PUT `/team`: `{team_id:int}`; same ownership validation, returns status.
- DELETE `/connection`: erases session/secrets/cache; `{connected:false}`.
- GET `/snapshot?refresh=false&compare_team_id=ID`: requires selection. Returns schema below. Optional compare ID must exist, default actual opponent. Refresh bypasses 60s session cache; failed refresh returns error, never stale data disguised as current.

Snapshot fields: `schema_version:1`, `fetched_at` UTC ISO, `source:espn_unofficial`, `league:{id,season_id,name,team_count,scoring_type,categories:[{key,stat_id,lower_is_better}],supported,unsupported_reason,lineup_slots:[string],acquisition_settings:{weekly_add_limit:int|null,limit_per_scoring_period:bool|null,season_add_limit:int|null}}`; actual categories validated against nine keys, scoring types H2H_CATEGORY/H2H_MOST_CATEGORIES. 14 teams is displayed, never assumed.

`period:{matchup_period_id,scoring_period_id,scoring_period_ids:[int],dates:[ISO date],remaining_dates:[ISO date]}`. Dates are derived from ESPN pro schedules for this matchup, America/New_York; games retain UTC start timestamps. `teams:[{id,name,ownership_verified,roster:[player],totals:stats|null,season_acquisitions:int|null,weekly_used_adds:int|null,remaining_adds:int|null}]`; `selected_team_id`, `opponent_team_id:int|null`, `comparison:{team_id:int|null,categories:[{key,user,opponent,state:winning|tied|losing|unknown}],wins,ties,losses}`. Missing stats are null; totals are current matchup cumulativeScore.scoreByStat, never season team aggregates. `matchup_history:[{matchup_period_id,home_team_id,away_team_id,home_totals,away_totals}]` contains available prior periods from current season.

Stats keys: pts,reb,ast,stl,blk,threes,to,fg_pct,ft_pct,fgm,fga,ftm,fta,minutes,games. FG/FT are recomputed from made/attempt when both exist (zero attempts -> null), otherwise reported percentage is retained. Player `id` string, `name`, `pro_team_id`, `positions` exact ESPN eligible slot names (UT normalized UTIL, BE BENCH, IR IR), `lineup_slot`, `injury_status`, `injured:bool|null`, `locked:bool|null` (unknown is never false), `availability:FREEAGENT|WAIVERS|ONTEAM|UNKNOWN`, `eligible:boolean` (only FREEAGENT, roster-excluded and valid slots), `current_rates:stats|null`, `current_games:number|null`, `prior_rates:stats|null`, `prior_games:number|null`, `schedule:[{scoring_period_id,date,start_at,opponent_pro_team_id,started:boolean}]|null`, `today:bool|null`, `remaining_games:int|null`. Season stat samples use actual aggregate split only, exclude projected and rolling splits; averages derive from games only when available.

`free_agents:[player]` bounded top 100 ESPN free-agent rows; WAIVERS rows exposed but eligible=false (claim timing unknown), all rostered IDs excluded. `free_agents_truncated:boolean`, `transactions:[{id,team_id,type,status,scoring_period_id,date}]|null` current scoring day only; no member IDs/cookies returned. ESPN season transactionCounter.acquisitions is not weekly usage. V2 uses the actual matchupAcquisitionTotals counter; weekly usage and remaining stay null only where verified counter/cap evidence is missing. `data_gaps:[string]` explains unavailable schedules/locks/injuries/prior samples/attempts/transaction counts. `optimizer:{status:requires_inputs,reason,endpoint}` points to the read-only planner; it does not itself generate recommendations. Projections, ownership certainty for public leagues, future minutes and probabilities are never invented.

Primary implementation evidence inspected 2026-10-31: https://github.com/cwendt94/espn-api (requests/espn_requests.py and requests/constant.py; basketball/league.py, player.py, constant.py, box_score.py, transaction.py; base_settings.py). This is source-author evidence for an unofficial client, not ESPN authorization or a service guarantee. No live private credentials tested.

## Verified counts, availability and protection metadata

See [Fantasy data V2](fantasy-data-v2.md) for the authoritative additive data contract, sources and tests. `mTransactions2` is current-day partial evidence; complete matchup counts use the separate `transactionCounter.matchupAcquisitionTotals` counter. Real `player.droppable`, league undroppable-list settings, team transaction locks and draft metadata are now exposed. Exact per-player drop-lock expiry remains unknown. Unknown health follows the user-authorized available-unless-explicitly-out policy with provenance; no new blanket confirmation requirement is introduced. The engine/UI own optional overrides and recommendation behavior. Actual transactions remain manual in ESPN.

Deployment: this API intentionally rejects LAN, hosted/nonloopback Host and nonloopback clients, even for public connect. Integration UI must show a local-only explanation instead of offering an unusable remote/private login. Run the existing single-process 127.0.0.1 service; browser must call its same-origin /api endpoints (Vite proxy may forward only local loopback requests). Do not loosen Host/client checks for deployment without adding authenticated user isolation, trusted-proxy policy and a real encrypted secret store.

Implementation finalized against mocked fixtures. See repository docs/espn-fantasy.md and code_review/espn-fantasy-backend.md; synthetic normalized example: sample-snapshot.json beside this contract. ## Integrated read-only planner

POST `/plan` uses the same loopback/Host/origin/header/session guards and shared four-worker pool as the other ESPN routes. JSON preferences are capped at 64 KiB and cannot contain client-supplied snapshots. Inputs: snapshot context (`league_id`, `team_id`, `matchup_period_id`, `fetched_at`), `candidate_ids`, `droppable_ids`, `max_stream_slots`, weekly cap/used/available counts with `user_confirmed_counts`, and `user_confirmed_eligibility`. Optional `player_overrides` supplies explicitly user-confirmed schedules and injured booleans; optional `remaining_dates` supplies confirmed current-matchup dates when coverage is missing. Optional `uncertainty_mode` is history or sensitivity; sensitivity requires all nine positive `margin_sd` values.

The server obtains its own current snapshot, validates context/ownership/eligibility/budget and protects every unselected roster player from drops. No new NBA/ESPN writes are performed. Output is the UI `WaiverPlan`: status ready/incomplete/unavailable; reasons/data_gaps; nullable baseline/projected `{totals,games,minutes,probability_five_wins}`; actions `{date,add_id,drop_id,stream_slot,gains,probability_gain}`; remaining_adds, assumptions, limitations, provenance and bounded-search diagnostics. Raw category assessments and opponent totals are retained in forecasts. Context mismatch returns unavailable with reconfirmation guidance; unsupported scoring and missing evidence never produce actions. See `docs/fantasy.md` for the supported user flow and algorithm limits.
