# Fantasy workspace

Fantasy opens on **Dashboard**. **Matchups** compares the current matchup against the actual opponent or any other league team using the same period's cumulative totals. Today's reported players appear below the category table. **Leaders** retains season rankings, comparison and device-local shortlist tools, with minimum games, minutes per game, total minutes and shooting-attempt filters. **Waiver Wire** offers recommendations only; all roster changes must be made manually in ESPN.

## Run and connect locally

Use `uv sync --all-extras --dev`, then `bun install --frozen-lockfile` and `bun run dev` in `nba_terminal/web`. Open `http://127.0.0.1:5173`. The proxy preserves the browser Host so same-origin ESPN protection works. For a local production build, run `bun run build` in that directory, then `uv run nba-terminal` from the repository and open `http://127.0.0.1:8000/fantasy`. Use a single backend process. Remote/LAN hosting and multiple backend workers are unsupported for ESPN sessions.

On Dashboard enter your league ID and ending season year (2027 for 2026–27), connect, then select your team. Public access cannot verify ownership. For a private league, sign in to ESPN yourself, open your browser's developer-tools Application/Storage cookie view for ESPN, and copy `SWID` and `espn_s2` into the local password fields. Never send cookies in chat, URLs, screenshots or reports. Fields clear on submission; secrets remain only in backend session memory. Disconnect or restart clears that session. This is unofficial cookie-based access, with no OAuth or password login. See [authentication and data limits](espn-fantasy.md).

## Enable a waiver plan

1. Refresh the league, then open Waiver Wire. Shortlist eligible unrostered free agents and select exactly which roster players may be dropped. All other roster players remain in baseline lineup forecasts and are protected from transactions. Editing the shortlist changes the planner's actual candidate pool; its displayed order expresses preference, while optimization chooses the schedule.
2. Verify the current matchup's weekly cap, adds already used and adds remaining in ESPN. If the cap is seven, enter 7 after verifying it. Confirm all three counts. The adapter enforces nonnegative integer counts and `used + remaining <= cap`; season acquisitions never substitute for weekly usage. ESPN's current-day transaction view cannot establish complete weekly usage.
3. Confirm the shortlisted players can be added and the selected drops are unlocked now. Unknown locks are not treated as unlocked without this explicit confirmation. Reported locked players cannot be selected. Review actual lineup eligibility and timing in ESPN before executing any recommendation.
4. Open **Complete missing schedules and availability** if instructed. Both full rosters matter. Explicit corrections can supply missing unstarted game dates and available/out status for the modeled remaining dates. Empty confirmed schedules mean zero remaining games. Known already-started games cannot be resurrected. These are clearly user-confirmed assumptions, not ESPN assertions. If matchup date coverage is missing, supply verified remaining dates in the same current matchup.
5. Historical estimates require at least three complete same-period prior comparisons with nonzero variation in all nine categories. When unavailable, use current baseline/rate comparisons, or explicitly choose **sensitivity** and enter nine positive margin standard deviations. Counting categories use category-total units; shooting percentages use fractions (`0.01` means one percentage point). No fixed uncertainty values are silently supplied. These results are uncalibrated sensitivity estimates, not probabilities established from live performance.

Any edit clears the previous recommendation; every successful snapshot replacement, team change or refresh resets confirmations. The backend validates league/team/week/timestamp scope and uses only its own authenticated snapshot. When a cache refresh changes the snapshot, refresh the UI and reconfirm. Missing rates, observed minutes, sample counts, shooting attempts, lineup rules or dates produce specific gaps and no actions. The table states when its baseline contains only recorded results and a future forecast is withheld.

The forecast combines recorded results with remaining eligible games and current/prior per-game rates. FG/FT use total makes divided by attempts; turnovers are lower-is-better; ties do not count toward five wins. Daily lineup matching, acquisition budgets and at most four rotating initial roster slots constrain plans. Injured/out players are conservatively excluded unless their availability is explicitly corrected. Search is bounded and approximate (500 plan evaluations in the production adapter, at most 40 shortlisted candidates); it may stop early or miss better combinations. ESPN's free-agent pool is itself a bounded sample. IR players are excluded from active forecasts and cannot be selected as initial drops. Known per-day acquisition budgets are unsupported and suppress plans. No waiver-claim clearance, dropped-player cooldown, same-day game-time transaction ordering, injury recovery, correlated category calibration or future role changes are modeled. See [algorithm details](fantasy_optimizer.md).

## Deterministic verification

From `nba_terminal/web`, `bun run e2e` runs existing mocked browser regressions. `bun run e2e:fantasy` builds the client and tests the actual production HTTP/session/normalization/planner chain through both Vite's proxy and production static serving. Its explicit test-only Python server replaces external ESPN/NBA transport with synthetic fixtures; it is never imported by production. No live credentials are required. User-specific real-league validation remains pending the user's own connection.
