# ESPN Fantasy backend security/cache review

Scope: read-only unofficial ESPN transport, normalized league data, local browser sessions and route registration. Self-review performed against correctness, API resilience, responsiveness, data honesty and maintainability. CODE_REVIEW_GUIDE.md was absent at the accepted base. This note is not an independent review or production security certification.

Findings addressed:

- Private credentials could leak through validation error bodies, repr or upstream exception strings. Connection bodies use bounded manual validation with static errors; clients/connections suppress secrets in repr; the worker catches unexpected exceptions without traceback logging. No credentials enter cache keys, URLs, files, normalized responses or browser storage. Requests contain only fixed-host GETs and disallow redirects.
- A local cookie API needs CSRF and DNS-rebinding boundaries. Every route checks loopback Host and client; mutations require a custom header and POST/PUT JSON; supplied Origin must match the served origin; cross-site Fetch Metadata is rejected. Session cookies are HttpOnly, Strict, scoped, time-limited, Secure on HTTPS. Remote/multiuser deployment is deliberately unsupported.
- Cancellation could release a worker slot while HTTP work continues. Worker tasks are shielded; slot release occurs after executor completion. Session memory and cache are capped, upstream connect/read timeouts are explicit and each streamed response is capped at 8 MB. Disconnect revokes immediately; concurrent/failed work clears revoked secrets in a finally block.
- Cross-browser cache reuse could expose private data. State/cache lives under separate random browser sessions, and reconnect/team changes revoke/invalidate correctly. Refresh failures never masquerade as fresh snapshots. Missing data is null, not stale success or zero.
- Season transaction counts could masquerade as weekly remaining adds. Counter names and explicit null weekly fields preserve scope; transaction rows are marked partial/current-day. Missing lock semantics remain null with required user confirmations documented.
- Percentages could be summed or tiny/rolling/projected samples could be treated as season averages. Made/attempt totals take precedence; zero attempts are null; only actual aggregate splits supply averages and games. Matchup totals come from current-period category results, with turnovers lower-is-better. Unsupported scoring remains visible.

Validation: deterministic transport/normalization/API tests cover ownership mismatch, isolated browsers, secret redaction, request restrictions, bounded payload failures, cache/refresh behavior, cancellations, disconnect during failed work, missing schedules and transaction limits. Full backend lint and coverage checks are recorded in task delivery evidence. No network tests use private credentials.

Remaining risks/limitations: unofficial endpoint schema/availability; untested real private cookies; SWID-to-owner comparison is local cookie consistency rather than independent OAuth identity; expired memory records prune lazily; Python reference deletion is not physical zeroization; current transaction view cannot prove complete weekly usage; unknown drop locks and injuries; bounded candidate pool and missing prior/history data can constrain recommendations; synchronous requests have per-connect/read timeouts rather than a global whole-snapshot deadline. Any hosted/multiworker rollout requires a separate authenticated secret/session design. Frontend and optimizer integration are outside this branch.
