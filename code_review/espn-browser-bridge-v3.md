# V3 ESPN browser bridge review

Base: 784a7e4ddd7e3c485ba77f030f3734298f3a74fd. Self-review only; CODE_REVIEW_GUIDE.md is absent at this base.

The bridge deliberately has no extension-origin CORS exemption, native host, general remote credential receiver, ESPN writes or page-to-extension message listener. Mandatory loopback Host/client, same-origin Origin/fetch-site, custom request header, JSON/body cap remain. Random host-only HttpOnly SameSite strict browser binding plus 30-second single-use ticket binds refresh to the requesting browser and exact app origin. Only the backend generates the final session cookie; submitted team IDs cannot redirect renewal. Current local code/extension and same-origin app scripts are trusted, as for manual connect. It cannot protect a user against malicious software taking over an already consented localhost origin or the browser itself.

Reviewed/fixed before handoff:

- Disconnect/re-pair revokes Pair.active before upstream work returns; completion checks it and clears uncommitted credentials. Concurrent refresh gets 409; nonce replay/forgery/expiry/unpaired/other-port requests rejected.
- Account change is latched until explicit re-pair. Missing cookies, permission denial, known expired/access-denied credentials revoke prior session; transient 5xx retains a still-valid prior session rather than disconnecting on network trouble.
- Backend owner membership and selected team checked with existing normalized service. Team changes update remembered pairing selection; renewals rotate session IDs and invalidate prior sessions.
- Manual fallback connect disables any prior automatic bridge. Extension Forget serializes consent changes with credential reads, preventing account-hash persistence from resurrecting revoked consent; active local tab then deletes bridge/session.
- Popup permission request runs directly in the click gesture. Consent names exact app origin, profile/store, and narrowly implemented two-cookie reads. Cookies are not in page DOM/events, URLs, storage or static error messages. Event payload is only advisory state; Firefox cloneInto handles cross-world object sharing. No listener accepts page commands.
- Inactive/missing pair does not read ESPN cookies. Cookie events filtered to two ESPN names. Hourly read validation and cookie-change refresh bounded; one-minute fallback, five-minute local/upstream error backoff. No ESPN network calls in async event loop.
- Extension memory may contain credentials transiently. Persistent extension data is scoped consent metadata and SHA-256 account identifier, not a credential or secret pairing token. Backend pairing/session capabilities live in HttpOnly local browser cookie and process memory; no ESPN credential persistence. Python does not guarantee physical RAM zeroization.
- Both unsigned ZIPs and actual setup guide included in wheel, served via fixed-name loopback-guarded allowlist. No path traversal or runtime filesystem generation.

Validation: real backend routes with mocked ESPN; extension JS with mocked browser APIs and loopback fetch. Tests cover existing cookie login, permission denial/revocation, no session, changed cookies/account, forged sender, wrong cookie store, cancellation/concurrency, transient errors, ownership, replay, capacity, package manifests and source artifacts. Configured full Python coverage gates pass. This is not an independent review or a live account/browser compatibility claim.

Remaining limits: Firefox temporary install is removed on restart; permanent normal Firefox requires Mozilla signing, not performed. Only normal first-party www.espn.com-readable cookies are supported (containers selected explicitly, no profile/partition scanning). Requires an open local app tab for detection/renewal; use app Disconnect before uninstall/closing all tabs if immediate revocation is required. Isolated real Firefox WebDriver attempt failed before session creation; both Bun/npx web-ext lint attempts exited 138 without a linter result. No user browser/profile/account modified. No consenting real private ESPN test performed. UI production-chain/visual checks belong to integrator after exact commit handoff.
